# BatteryCopilot 300 案例评测协议

这套评测检查公开电池资料查询与模拟变更复核流程。300 是案例数，
对应 41 种题型或流程；不代表 300 种独立业务逻辑，也不代表工业现场验证。
每个案例有明确输出、来源和评分条件。

## 历史解析快照要求

已发布的900次尝试对应当时的703元素Docling解析结果。独立安装时重新解析同一PDF，
本机得到753个元素；元素遍历编号与部分分块发生变化，旧指南UID不能直接用于新解析结果。
题库标准答案和页内区域现已固定在标注文件中，生成300题不再依赖本机解析缓存，
原有题干、金标准、题库SHA-256及900次成绩均未改变。

执行含指南题的评测前，执行器检查解析快照指纹；不同则在调用模型之前停止，
避免把编号变化计作模型能力差异。保留了旧解析的本机可使用 `documents --reuse-parsed`
重建旧索引。原PDF解析全文不随仓库发布，因此**干净检出不能直接复现旧指南题成绩**；
需要取得原解析快照，或针对新解析结果独立重新标注并建立新题库、重新评测。
新安装仍可浏览与检索指南，制造验证也可独立重现。

## 题库与来源

| 类别 | 案例 | 所检查的能力 |
| --- | ---: | --- |
| 台账核对 | 50 | 分类计数、部件编号、不同类型的同号对象 |
| 连接关系 | 50 | 连接两端、共用部件、移除操作、对象类别 |
| 记录顺序 | 50 | 前序、后继、连续步骤、操作对象切换 |
| 指南证据定位 | 50 | 工艺约束、质量检查、工序清单、连接技术及安全条目 |
| 资料边界 | 50 | 缺失字段、未知年份、产品范围、拆解记录适用范围 |
| 变更流程 | 50 | 补资料、修订规格、冲突纠正、部分解决、撤回资料 |

- [完整案例与答案](../data/benchmark/cases.json)、[可读目录](../data/benchmark/catalogue.md)。
- CSV 答案由独立的原始行读取器计算，不调用被测图查询或规则实现；来源记录文件及物理行号。
- 指南答案根据 PDF 原页及栏位置核对，保留页码、区域和证据 UID；
  [标注](../data/benchmark/guide-annotations.json)由开发助手核对，未经外部工程师审阅。
  不根据解析器继承的栏目标签直接产生答案，不分发指南全文。
- 变更资料为显式模拟输入，原始数据仅证明目标及连接关系，不能证明 M6/M8 等规格。
  10 种流程各有 5 个产品情境，规格判断按预先声明的独立状态表计算。
- 来源文件及题库 SHA-256 见 [manifest](../data/benchmark/manifest.json)。

开发集 60、测试集 240，每类分别为 10/40。
CSV 与变更案例按产品隔离：产品 1–2 用于开发，3–10 用于测试；
指南按页隔离：第 6、7、14 页用于开发，其余选定页用于测试。
检索语料包含全部产品和页面；隔离的是任务及标准答案，不是系统的知识库。
部分题型跨集共享，所以这是产品/页面情境迁移测试，不是全新题型泛化测试。
以往的 20 题、补充题及检索测试仍属于开发检查，不并入本套分母。

## 三种方案

| 方案 | 检索与决策策略 |
| --- | --- |
| A：固定 RAG | 同一个混合检索器返回最多 12 条，随后模型作答 |
| B：固定图查询与规则流程 | A 的检索结果，加统计、锚点原始记录、一跳关系、局部序列及最多两次邻居展开；指南题读取指定整页；变更题运行规则 |
| C：生产 Agent | 自行选择现有领域工具，多轮补读证据，使用生产环境的引用检查 |

三种方案使用相同 Terra 模型、语料、问题、产品范围及模拟输入；
执行器不把答案、题型、评分字段或标准来源集合传给模型。
问题本身声明输出键和可供查询的对象、页码等线索。
A/B 的预检索直接使用这些线索，C 在用户消息中收到同样线索。

每个分析阶段最多 8 次模型调用、12 次工具调用；
Answer 结构化提交计为模型调用，不计为领域工具调用。
固定方案的预算用尽后不再追加查询；Agent 预算耗尽且未回答则记失败。
这些是上限，不是相等的实际算力：A 的工具更少，B 可读取指定整页，
C 单次混合检索沿用生产默认 6 条。报告需同时披露实际调用量与 token。
B 是较强的固定流程对照；对比反映整套执行策略，不能只归因于模型规划。

模型通过已登录的 Codex CLI 调用 gpt-5.6-terra，low reasoning，
每轮独立临时目录，关闭自身 shell、文件修改和 web 工具，仅选择宿主领域工具。
模型不能读取仓库中的答案。输入输出 token 为 CLI 返回的观测值，不据此推算 API 费用。
失败轮次可能没有 usage；计时包括本机查询和 CLI 开销，并发会影响延迟。

## 评分与运行

答案写入现有 `Answer.summary` 的 JSON 字符串，claims 提供解释和引用。
这是为了确定性评分而规定的输出格式；格式不合法、字段缺失或多余均计失败。
不以另一模型充当裁判。

1. **答案正确**：所有指定字段匹配。标明顺序的列表逐项匹配，其余列表允许换序，
   不允许用重复值充数；布尔值与数字不混用。
2. **答案与引用同时通过**：答案正确，覆盖全部标准来源，且每条引用都能在该阶段
   实际取得的证据中解析。统计可引用完整统计证据，也可引用全部相关原始行。
   “当前产品不存在此编号”没有正向事实行，来源列出用于独立核对的当前产品完整台账。
3. 指南题测的是**条目定位与覆盖**。不将定位正确声称为自然语言解释的语义正确。
   引用检查也不等于自动证明每句 claims 都被来源蕴含。
4. 50 个变更案例包含 95 个分析阶段：正常流程一阶段，其余修订前后两阶段。
   两阶段全部通过才算该案例通过，不能把 95 阶段报成 95 个案例。

完整一轮为 300 × 3 = **900 个案例尝试，1,035 个分析阶段**。
每题每方案一次；失败、超时及无答案都保留在分母。
先用 10 个开发案例做管线试跑，再冻结题库、源码和配置开展完整评测。
正式测试后不因失败修改答案、删题或只保留重试成功结果。
不同代码或数据版本使用不同输出目录；恢复运行只跳过已记录尝试。

```powershell
$env:PYTHONUTF8 = '1'
# 模型已经缓存时避免 Hugging Face 的联网元数据等待
$env:HF_HUB_OFFLINE = '1'
uv run python -m battery_copilot.benchmark_cases
uv run pytest -q
uv run python -m battery_copilot.benchmark --output data/runs/benchmark-300 --workers 6
uv run python -m battery_copilot.benchmark --output data/runs/benchmark-300 --summarize
```

运行 manifest 保存源码、数据及锁文件哈希和配置。`attempts/` 保存每次实际回答、
工具返回、评分、耗时与可用的 usage；`summary.json` 汇总开发/测试集和各类别。
这些原始运行记录留在忽略目录 `data/runs/`，公开仓库保留题库、执行器、协议和结果摘要。
结果只支持这套公开资料及模拟流程下的结论。

完整运行后重放 50 个保存流程，再生成公开报告：

```powershell
uv run python scripts/benchmark-workflows.py --run data/runs/benchmark-300
uv run python scripts/publish-benchmark.py data/runs/benchmark-300 --commit <冻结源码提交>
```

重放复用实际 C 回答，不再调用模型。复核人由脚本模拟，验证应用的状态流转，
不能把它算作人工验收。发布脚本要求全部 900 个尝试和 50 个流程结果齐全。
题库 manifest 的 `sha256` 按 UTF-8、LF 换行的 JSON 文本计算；
运行 manifest 的逐文件指纹按本机原始字节计算，跨平台核对需注意文本换行。
