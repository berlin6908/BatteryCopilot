# 制造业务诊断集 v1

这套评测检查 KIproBatt 制造功能中的可核查任务，不替代真实工程师验收。
36 个案例由开发助手逐题编写业务问题与差异点；覆盖 12 个测试批次，
其中 2 个批次的 6 题用于开发检查，另外 10 个批次的 30 题用于冻结评测。
两部分涉及的原始证据文件没有重叠。源知识库仍包含全部数据。

本轮108次尝试已经完成，分项成绩、失败分析和调用量见 [实测结果](manufacturing-results.md)。

| 任务 | 数量 | 业务差异举例 |
| --- | ---: | --- |
| 对象履历 | 4 | 三状态与四状态、过程去重、仅有当前对象的断链 |
| 工序参数 | 7 | 1.1/2.1 ml、转录草稿核对、ml→µl、g→kg、注入与封口压力 |
| 缺失资料 | 6 | 空值与零值、湿质量有值但干质量为空、缺少上游注液资料 |
| 循环定位 | 10 | 中段、末段、相邻循环、短文件中不存在的循环 |
| 对象与文件身份 | 4 | 同一文件挂接两个状态对象、误贴其他电芯文件、非常规文件名 |
| 判断边界 | 5 | 可核查资料与质量放行、微小非零值、容量变化与SOH、记录数量与寿命 |

来源为 [KIproBatt v0.3.2](https://zenodo.org/records/11895571)，
署名、许可和数据边界见 [ATTRIBUTION](../data/sources/kiprobatt/ATTRIBUTION.md)。
采用真实实验室制造数据；题目中的交接要求和转录草稿是评测任务设定。
没有生成虚构制造测量值，也没有把“未提供质量标准”替换成通用工业阈值。

## 标准答案如何形成

题库和来源在 [cases.json](../data/manufacturing-benchmark/cases.json)，
归档校验、题库和源文件指纹在 [manifest.json](../data/manufacturing-benchmark/manifest.json)。

`manufacturing_cases.py` 直接读取原始 JSON-LD 节点及测试文本，
不调用生产导入器、Neo4j 查询、Agent 工具或生产数值解析器生成标准答案。
JSON-LD 保留原节点与 IRI；循环答案使用标准 CSV 库和 Decimal 解读原始单元格，
记录物理行号。单位转换和算术在标准答案侧独立计算。
断链和拒绝越界判断的规则事先写在业务问题及标注中，不依据模型输出修改答案。

“逐题编写”表示问题和差异点由开发助手编写；取数、单位换算和材料化题库由程序完成。
这不是外部专家的独立标注，也不是盲测的真实用户问题集。
部分题目的缺失/判断边界条件能从题干猜到，所以下面保留不提供资料的对照。

## 三个对照

| 策略 | 可用资料与动作 |
| --- | --- |
| no_data | 相同模型与问题，不提供任何档案或工具证据；主要衡量题干提示及常识能得到多少答案 |
| fixed | 固定读取完整对象链、每个相关过程的参数、每份测试文件首尾各12行；再让模型作答 |
| agent | 使用产品实际的四个领域工具，自行追溯、查参数、翻测试页、读取原始来源 |

所有策略使用同一模型、系统指令、问题和输出约定，不向模型传标准答案、题型标签、
评分字段值或标准来源集合。Codex CLI 只能返回宿主工具选择，不能用自身文件或网页工具。
`run_analysis` 是产品 `run_report` 使用的同一取证循环；评测不生成假人工复核记录，
也不把评测回答写进用户的报告列表。

每题上限为 10 次模型调用、16 次暴露给模型的工具调用。固定档案内部的实际查询另行计数。
这是相同上限，不是相同实际 token 或查询次数。固定档案不因题目内容改变采样页，
中段题的差异可以说明自适应取证的作用，不能据此证明 Agent 普遍优于完整档案检索、
规则查询或其他 RAG 实现。此处没有将旧 KIT 检索器冒充制造数据的 RAG 基线。

## 评分与适用范围

为便于核查，题目要求将特定字段写入 `Answer.summary` 的 JSON 字符串，
`claims` 保留说明与引用。评分分两层：

1. **字段答案通过**：所求字段完整且匹配。布尔值和数字不同，null 和0不同，
   链顺序必须正确；普通数值允许约定的六位小数误差，微小数值单独保留精度，
   原始零值不允许拿微小非零值替代。
2. **答案与来源同时通过**：字段正确，覆盖预先声明的参数/文件/循环行或追溯结果引用，
   且全部引用均来自该次成功返回的工具证据。

引用覆盖不等于逐句语义蕴含验证；字段评分不评价自然语言报告的完整性、措辞或实际建议效果。
因此报告中的分数称为“本诊断集的字段/来源通过率”，不称“工业问题解决率”。
36题规模较小，批次内案例相关、题型共享；不以题目数代替独立样本量。
未加入跨电芯工艺比较、变更影响传播或多模态工程图理解，因为产品目前尚未提供相应工具。
这些是后续功能与业务验收范围，不因当前单电芯评测通过而视为已经实现。

## 重现

以下命令针对v1源码检查点 `14f44b8`。当前执行器已用于
[v2验证](manufacturing-validation.md)，重现v1时先在独立检出中使用该检查点，
按该版本README准备环境和导入数据。题库重建只读取原始归档，不要求数据库：

```powershell
$env:PYTHONUTF8 = '1'
$env:HF_HUB_OFFLINE = '1'
uv run python -m battery_copilot.manufacturing_cases --archive data/sources/kiprobatt/dataset-v0.3.2.zip
uv run pytest -q
uv run python -m battery_copilot.manufacturing_benchmark --output data/runs/manufacturing-benchmark-v1 --split dev --workers 3
uv run python -m battery_copilot.manufacturing_benchmark --output data/runs/manufacturing-benchmark-v1 --split test --workers 3
uv run python -m battery_copilot.manufacturing_benchmark --output data/runs/manufacturing-benchmark-v1 --summarize
```

运行清单冻结源码、题库、锁文件及模型配置的哈希。每题每策略尝试一次，所有失败留在分母。
中断续跑只跳过已经保存的尝试；源码或配置变化必须换输出目录，不能用重试覆盖失败。
原始回答与工具轨迹在忽略目录 `data/runs/`；开源仓库仅保存题库、执行器、协议与结果摘要。
