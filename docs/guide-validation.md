# 工艺指南：引用稳定性与多语言检索

2026-09-14，源码检查点 `f739792`。目标是重新解析后仍能打开已引用的原文，
并修复中文、德文检索中的布局证据漏检。使用同一份 28 页 PEM 指南；未调用生成模型评分。

## 来源定位

指南 UID 改为 `pem:<PDF SHA-256>:p<页码>:<归一化区域坐标>`。
引用读取直接按 PDF 版本、页码和矩形提取原文，不依赖当前 Docling 元素编号或图数据库索引。
这采用文档区域选择器的常见模式，参见 [W3C Web Annotation](https://www.w3.org/TR/annotation-model/#fragment-selector)。
模型取回的文字和界面高亮对应同一原文区域；索引文本仍可包含标题上下文。

重新解析同一 PDF 得到 703 与 753 个区域，其中 678 个 UID 相同。
旧解析中另有 25 个区域不再出现在新索引中，**25/25 仍可由 PDF 打开**；
23 个有原生文字，2 个仅有图形，需要查看原页。
[核对记录](../data/guide-validation/region-stability.json)与真实 PDF 的重排、拆分回归测试一并保留。
这证明旧区域可独立解析，不意味着不同解析器总会生成相同的框。
本地需要保有引用指定版本的 PDF。原顺序编号引用不再作为当前接口格式。

布局图中的 Buffer zones、Rework stations 等原生文字此前被通用图片占位文本替代。
现在复用 PDFium 提取图框内文字；正文标题按水平重叠关系关联，修复居中标题被漏掉的问题。
没有增加视觉模型或 OCR；对没有原生文字的图形，仍只能返回页面位置。
重导入会替换派生指南节点，保存报告中的来源快照保留。

## 检索和评分

保持 E5-small + Neo4j HybridRetriever，指南查询扩大向量候选池后，对前 100 个混合候选
使用现有 SentenceTransformers 库中的
[多语言 mMARCO MiniLM CrossEncoder](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)
重排，返回前 6 个。模型版本固定，不新增 Python 包。
[Neo4j 的 effective_search_ratio](https://neo4j.com/docs/neo4j-graphrag-python/current/api.html)
设为 6；仅增加候选数仍未修复新解析中的布局漏检，因此保留了重排。
KIT 混合查询和制造图查询保持原策略。

[20 个问题](../data/guide-validation/cases.json)包括原有 8 道开发探针，以及 4 个新增意图
各自的中、英、德表达：超声焊头空间、键合线熔断保护、BMS 装配、过压风险。
新增问题根据原始 PDF 页和区域标注，先固定题目再查看检索结果。
开发过程中已查看这些问题，最终结果属于修复验证；JSON 中的 `test` 只是原始划分标签，
不能据此宣传为独立盲测，也不能把翻译后的 12 问当作 12 种独立业务任务。

- 页 Hit@6：前六条中至少一条来自正确页。
- 原文区域 Hit@6：同页返回框的并集覆盖标准区域至少 80%。重叠框不重复累计，允许解析后分块。
- 原文区域指标仍不能证明生成答案正确；整张图的范围较大时也可能覆盖目标，不是语义支持评分。

这些是后续检索质量工作，不修改答案或扩大命中窗口来消除失败。

本机 CPU、两个计算线程、已下载模型缓存：第一次查询含模型初始化为 **42.875 秒**；
其余 19 次查询中位数 **6.04 秒**。这是小规模本机实测，不是服务 SLA。
索引命令预先下载重排模型，首次在线查询仍需加载模型。

## 重现

完成 README 数据导入后运行；不需要生成模型额度：

```powershell
$env:PYTHONUTF8 = '1'
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'
uv run python -m battery_copilot.guide_evaluation --output data/runs/guide-validation.json
```

首次导入会下载两个检索模型。不同机器或重新建立的近似向量索引可能产生不同排名，
应发布实际结果及其语料指纹。原 300 题的指南结果仍属于历史顺序编号和解析快照，
题库、成绩未改写，详见[历史评测协议](benchmark-300.md)。
