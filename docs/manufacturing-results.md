# 制造业务诊断实测结果

2026-09-14（Europe/Berlin），使用 `gpt-5.6-terra`，通过项目现有 Codex CLI 接口运行。
36 题、三种策略，共完成 **108 次尝试**；其中开发集 18 次、冻结评测 90 次。
开发检查后没有调整源码、题目或提示，运行结束核对全部冻结文件哈希一致。
每个组合只运行一次，两个运行错误均保留在分母，未重试覆盖。

题目、来源和评分约定见 [诊断协议](manufacturing-benchmark.md)。
可读取的结果位于 [results.json](../data/manufacturing-benchmark/results.json)，
模型配置及源码指纹位于 [run-manifest.json](../data/manufacturing-benchmark/run-manifest.json)。
原始回答和工具轨迹保存在本机 `data/runs/manufacturing-benchmark-v1/attempts/`。

## 冻结评测：30题，10个测试批次

| 策略 | 严格字段通过 | 字段及预设引用同时通过 | 单题耗时中位数 |
| --- | ---: | ---: | ---: |
| 不提供资料 | 2/30（6.7%） | 0/30（0%） | 6.99秒 |
| 固定档案 | 22/30（73.3%） | 20/30（66.7%） | 14.57秒 |
| Agent | 27/30（90.0%） | 24/30（80.0%） | 21.92秒 |

字段评分要求键集合、类型和值都匹配，因此格式错误也会导致整题失败。
预设引用评分检查指定证据标识的覆盖，不等于逐句语义正确性。
下文把运行错误、字段格式、缺少目标数据和引用覆盖分别列出。
这些是小规模自建诊断集的通过率，不能作为工业业务准确率。

Agent 在循环定位上的优势最明显：它会继续读取中段数据。
固定档案只提供首尾各12行，缺少某些所求循环时返回 null 是适当的行为，但无法完成该任务。
本结果支持“自适应取证能够补足固定采样缺口”，不支持“Agent 普遍优于固定查询或 RAG”。

## 失败分析

| 策略 | 案例 | 发生了什么 |
| --- | --- | --- |
| Agent | mfg-07、mfg-18 | 分别请求302行和120行，超过工具单次40行上限；异常中止了取证循环。mfg-07其实已取得所需履历，还继续查了不必要的循环数据。 |
| Agent | mfg-22 | 正确找到 ACR/DCIR 的零值，但输出字符串 `"0"`，没有遵守数值类型约定；这不是把零误读成缺失。 |
| Agent | mfg-09、mfg-11、mfg-30 | 字段正确，引用了实际读到的关联参数或过程，但未覆盖约定的文件/追溯结果 UID。 |
| 固定档案 | mfg-18、mfg-20、mfg-23、mfg-25、mfg-29、mfg-34 | 所需中段循环不在首尾采样中，部分或全部数值返回 null。mfg-25还多输出了一个 `cycle` 键。 |
| 固定档案 | mfg-07 | 正确列出四个对象状态和三个过程，却输出了对象字典列表与过程名称列表，而标准答案要求名称列表与过程数量。题目未把这两个类型讲清楚，这是题目表述问题。 |
| 固定档案 | mfg-33 | 两个所求字段和值均正确，额外输出了 `wet_cell_mass`，严格键集合评分不通过。 |
| 固定档案 | mfg-11、mfg-26 | 字段正确，但引用没有覆盖约定的完整追溯结果 UID。 |

Agent 合计6题未同时通过：2题运行错误、1题字段类型、3题引用覆盖。
固定档案合计10题未同时通过：6题采样缺口、2题输出结构、2题引用覆盖。
所有108次尝试中，没有出现评分器发现的“引用未在该次工具证据中出现”情况；
这不证明引用足以支持所有自然语言陈述。

无资料策略通过 mfg-11、mfg-35 的字段检查：两题答案恰好都是 null。
它没有查到对应证据，来源评分为0。这说明仅靠字段分数会把保守猜测计为答对。

运行后发现的表述和评分局限没有回填到本轮题库，也未据此重新计算更好看的成绩。
特别是 mfg-07，不能把固定档案的结构不匹配解释成不理解对象履历。

## 下一轮优先项

1. 明确工具的分页范围，让可纠正的参数错误返回给 Agent；已有足够证据时及时结束取证。
2. 改善整条履历、文件统计和资料缺口的引用选择，同时用具体案例审查“等价来源”是否被评分排除。
3. 新版本题库明确字段类型，尤其是名称列表、数量、原始数值；保留本轮题库和原始分数供比较。
4. 修复后补充能按问题定位目标循环的固定查询对照，再用新批次检验；扩大业务能力时优先做跨电芯工艺参数比较。

本轮尚未实现上述修复或跨电芯工具。36题覆盖的是单电芯履历与检验资料核查，
跨电芯比较、变更影响传播和多模态理解仍需各自实现与验收。
